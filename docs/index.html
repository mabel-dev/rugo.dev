Traditional libraries optimise decoding speed. Rugo optimises reading less data in the first place — pushing column projection and predicate pushdown ahead of decode, so data you don't want is never touched. Extracted from years of work on the Opteryx SQL engine.

Philosophy

Performance doesn't only come from decoding faster.

Often it comes from avoiding decoding data you don't need in the first place. Rugo was built as the file layer for the Opteryx SQL engine, where the goals were simple: read as little data as possible, hold as little in memory as possible. Column projection and row-group pruning happen before any decoding — so the columns and rows a query doesn't need are never paid for. The result is a library that gets faster the more selective your query is, stays tiny on disk, and carries no PyArrow, Pandas, or NumPy into your environment.

⚡

Faster cold starts

AWS Lambda and GCP Cloud Functions bill by memory and duration, and every cold start pays for the imports. Rugo's cold import is roughly 2.8× to 12× faster than PyArrow, DuckDB or Polars — 15 ms against 41, 70 and 171 — and it adds up fast at scale-out.

📦

Smaller packages, no dependencies

At 9× smaller than PyArrow and 13× smaller than Polars, rugo shrinks Lambda deployment packages and container images, speeds up deploys, and leaves almost all of AWS Lambda's 250 MB unzipped limit for your own code. The wheel bundles everything it needs, so pip install rugo is the entire dependency story.

🔍

Lower memory, more selectivity

Column projection and row-group pruning are first-class citizens. Skip the columns you don't need. Skip the row groups that can't match. The more selective the query, the bigger rugo's advantage — and Parquet reads peak at up to 2.2× less memory than PyArrow.

What rugo doesn't chase

Being a query engine. Joins, SQL and aggregations belong to Opteryx, the engine built on rugo. Rugo stays the file layer, and wins where serverless and embedded workloads actually hurt: a package 9× smaller, a cold start nearly 3× faster, and up to 2.2× less peak memory than PyArrow.

Performance

The gap is projection, not decode speed.

Rugo wins by decoding less — up to 21× faster than PyArrow on selective JSONL reads. The more columns and rows a query lets rugo skip, the bigger the win, and even when it has to read everything it is still 2.7× faster. On Parquet, parallel row-group decode keeps it level with DuckDB, Polars and PyArrow.

Files. The wide file is 1,000,000 rows by 100 columns of integers, floats and strings, 509 MB, zstd, 20 row groups of 50,000 rows, written by PyArrow with no bloom filters. Queries. "2 columns" selects a and b; the filtered queries keep ~10% and ~1% of rows by k; "SELECT *" reads the narrow file in full; count(*) reads only the footer's row count.

When to use rugo

Rugo is for reading, not loading.

Rugo is the file layer under Opteryx, the SQL engine it was built for. Use it directly to scan Parquet with column projection and predicate pushdown and stream the result as Morsels, with no query engine in the way. When you want SQL, reach for Opteryx, which runs on rugo.

🪶

Choose rugo when

  • package size, cold start or dependency count matters: Lambda, Cloud Run, containers, embedded
  • the workload is selective: a few columns, a filter, a slice of the file
  • you want a streaming Morsel interface and a small, steady memory footprint
  • you need file I/O, not a query engine
🦖

Choose Opteryx when

  • you want to write SQL over your Parquet, JSONL and CSV files
  • you need joins, aggregations and a query planner
  • you want projection pruning and predicate pushdown handled for you, on the same rugo readers

Where the Parquet advantage comes from

Rugo's Parquet advantage is reading less, not raw scan throughput. Row-group pruning and column projection cut what is decoded and keep peak memory low.

from rugo import parquet

# Metadata only — no column decode
meta = parquet.read_metadata("planets.parquet")
print(meta.num_rows)
print([c.name for c in meta.schema_columns])

# Selective streaming read
with parquet.read_parquet(
    "planets.parquet",
    columns=["id", "name"],
    predicates=[("id", ">", 4)],
) as reader:
    for morsel in reader:
        names = morsel.column("name").to_pylist()

# Write (ZSTD default)
data = parquet.write_parquet(morsel)
with open("out.parquet", "wb") as f:
    f.write(data)

# Stream batches at constant memory — one row group per call
with open("out.parquet", "wb") as f:
    with parquet.open_parquet_writer(f.write) as writer:
        for batch in batches:
            writer.write_row_group(batch)

No predicates on read

Avro carries no statistics, so there's no predicates argument — filter the morsels you get back. Avro timings are in Performance.

from rugo import avro

# Writer schema and codec, from the header — no record decoded
meta = avro.read_metadata("launches.avro")
print(meta.codec, meta.columns)

# Projected read — dotted names reach into nested records
with avro.read_avro(
    "launches.avro",
    columns=["Company", "Rocket.Name"],
) as reader:
    for morsel in reader:
        print(morsel.column("Rocket.Name").to_pylist())

# Read through a reader schema — drop, add (with defaults) or widen fields
schema = {"type": "record", "name": "Launch", "fields": [
    {"name": "Mission", "type": "string"},
    {"name": "Source", "type": "string", "default": "archive"},
]}
with avro.read_avro("launches.avro", reader_schema=schema) as reader:
    for morsel in reader: ...

# Write — one call, or streamed batch by batch
data = avro.write_avro(morsel, codec="zstandard")
with open("out.avro", "wb") as f, avro.open_avro_writer(f.write) as writer:
    for batch in batches:
        writer.write_batch(batch)

Data Model

Vectors and Morsels.

Rugo speaks Draken — a bundled columnar substrate that ships inside the wheel. There are two objects you will encounter.

Vector

A single typed column (similar to an Arrow Array).
to_pylist() → list  ·  materialise as a Python list
is_null() → Vector[bool]  ·  null mask, one bool per row
null_bitmap() → bytes  ·  raw 1-bit-per-row null bitmap
in_list(values) → Vector[bool]  ·  membership test
between(lower, upper) → Vector[bool]  ·  inclusive range test
sum() / min() / max() → scalar  ·  typed reductions; null-aware
take(indices) → Vector  ·  gather rows by index list
to_arrow() → pyarrow.Array  ·  interop; requires PyArrow at runtime
type property  ·  Draken type tag (e.g. DRAKEN_VARCHAR)
len(vec) → int  ·  row count
vec = morsel.column("name")
values = vec.to_pylist()  # ["Mercury", "Venus", …]

Morsel

A batch of rows across columns (similar to an Arrow RecordBatch).
column(name: str) → Vector  ·  return a single column by name
column_names property → list[bytes]  ·  ordered column names
column_types property → list  ·  Draken type per column
schema property → list[dict]  ·  name + type per column
select(col_names: list) → Morsel  ·  project to a subset of columns
rename(new_names: list) → Morsel  ·  rename columns in order
filter_mask(mask: Vector[bool]) → Morsel  ·  keep rows where mask is true
take(indices) → Morsel  ·  gather rows by index list
slice(offset, length) → Morsel  ·  contiguous row window
combine(morsels) classmethod → Morsel  ·  concatenate a list of Morsels
from_vectors(col_names, col_vecs) classmethod → Morsel  ·  construct from column name/vector pairs
to_arrow() → pyarrow.Table  ·  interop; requires PyArrow at runtime
len(morsel) → int  ·  row count
num_columns property → int  ·  column count
nbytes property → int  ·  approximate memory footprint in bytes
for morsel in reader:
    print(len(morsel), "rows")

A read → write round-trip works naturally: read_parquet yields Morsels, write_parquet / write_csv / write_jsonl all consume a Morsel. 

from rugo import parquet
from rugo.csv import write_csv
from rugo.jsonl import write_jsonl

with parquet.read_parquet("planets.parquet") as reader:
    for morsel in reader:
        csv_bytes   = write_csv(morsel)
        jsonl_bytes = write_jsonl(morsel)
        pq_bytes    = parquet.write_parquet(morsel)

Rugo isn't just designed to decode data faster.
It's designed to avoid decoding data you don't need.

Rugo was born out of Opteryx's need for a fast, low-memory Parquet reader — thin by design, and opinionated about what not to load.
