Validate Parquet files the moment they land in S3

Justin Joyce · 18 November 2026 · 8 min read

aws lambda s3 parquet data quality how-to

Correct at time of publishing, tested with rugo 0.5.12. For up-to-date performance and feature information, see rugo.dev.

A broken Parquet file is cheapest to catch in the second it arrives, before a dashboard, a dbt model or a nightly job trips over it. This post builds a small AWS Lambda that checks every .parquet object as it lands in S3, promotes the good ones, and quarantines the bad ones with a report that says exactly what was wrong. The whole deployment package is about 15 MB.

The shape of it

Producers write to incoming/. S3 invokes the function for each new object. The function either moves the file to validated/, where downstream jobs read from, or to quarantine/ next to a JSON report. 

producer ──▶ incoming/x.parquet ──▶ Lambda ──┬──▶ validated/x.parquet
                                                 └──▶ quarantine/x.parquet
                                                      quarantine/x.parquet.report.json

Because the trigger only watches incoming/, the moves and the report never invoke the function again. Consumers only ever see files that passed.

What "valid" means

Four checks, cheapest first. Each one stops at the first family of problems it finds, so the report stays readable.

  1. It is Parquet. The footer parses. Truncated uploads, zero-byte objects and CSVs renamed to .parquet all fail here.
  2. The schema matches your contract. Every expected column is present with the expected type, and nothing unexpected has appeared.
  3. Every row group decodes, and the number of rows decoded equals the number the footer promised. Damaged data blocks are caught, and the error names the row group and column.
  4. Required columns are never null.

Try it on your laptop first

The whole thing is plain Python, so build and test it locally before touching AWS. Install rugo and grab the sample file used throughout the rugo docs, 4,630 rocket launches: 

pip install rugo

rugo diff space_missions.parquet drift.parquet; echo "exit code: $?"
~ changed:
name        left_type      right_type  left_nullable  right_nullable
----------  -------------  ----------  -------------  --------------
Lauched_at  timestamp[us]  varchar     True           True
exit code: 1

The validator

The checking logic lives in one function, validate(), that takes a path (or the bytes of the file) and returns a list of problems. An empty list means pass. No AWS in sight, which is what makes it easy to test. 

import json
import os
import urllib.parse

import boto3
from rugo import parquet

s3 = boto3.client("s3")

# The contract: column name -> the logical type rugo reports for it.
CONTRACT = {
    "Company": "varchar",
    "Location": "varchar",
    "Price": "float64",
    "Lauched_at": "timestamp[us]",
    "Rocket": "varchar",
    "Rocket_Status": "varchar",
    "Mission": "varchar",
    "Mission_Status": "varchar",
}
NOT_NULL = ["Company", "Mission", "Mission_Status"]


def validate(source):
    """Return a list of problems. An empty list means the file passed.

    `source` is a path or the bytes of the whole file.
    """
    # 1. Is it Parquet at all? The footer must parse.
    try:
        meta = parquet.read_metadata(source)
    except Exception as exc:
        return [f"not a readable Parquet file: {exc}"]

    problems = []
    if meta.num_rows == 0:
        problems.append("file has no rows")

    # 2. Does the schema match the contract?
    actual = {c.name: c.logical_type for c in meta.schema_columns}
    for name in CONTRACT.keys() - actual.keys():
        problems.append(f"missing column: {name}")
    for name in actual.keys() - CONTRACT.keys():
        problems.append(f"unexpected column: {name}")
    for name in CONTRACT.keys() & actual.keys():
        if actual[name] != CONTRACT[name]:
            problems.append(f"{name}: expected {CONTRACT[name]}, found {actual[name]}")
    if problems:
        return problems

    # 3. Does every row group decode, and do the row counts agree with the footer?
    try:
        decoded = 0
        with parquet.read_parquet(source) as reader:
            for morsel in reader:
                decoded += len(morsel)
        if decoded != meta.num_rows:
            problems.append(f"footer says {meta.num_rows} rows, decoded {decoded}")

        # 4. Are the columns that must never be null actually non-null?
        for name in NOT_NULL:
            with parquet.read_parquet(
                source, columns=[name], predicates=[(name, "is null", None)]
            ) as reader:
                nulls = sum(len(m) for m in reader)
            if nulls:
                problems.append(f"{name}: {nulls} null values")
    except Exception as exc:
        problems.append(f"decode failed: {exc}")
    return problems

Two things worth noticing. The schema check reads only the footer, so a file with the wrong shape is rejected without decoding a single byte of data. And check 4 reuses rugo's predicate filtering: asking for rows where a column is null and counting what comes back is the whole null check, with no loop over values.

Run it over the files you just made:

python3 - <<'EOF'
import lambda_function as lf

for f in ["space_missions", "truncated", "notes", "drift"]:
    print(f"{f}.parquet ->", lf.validate(f"{f}.parquet") or "passed")
EOF

The Lambda handler

The handler is the thin AWS layer around validate(). rugo reads a path or a bytes buffer rather than an s3:// URL, so the handler downloads each object to /tmp with boto3, which the Lambda runtime already includes, and hands rugo the path. 

def _tag(bucket, key, result):
    s3.put_object_tagging(
        Bucket=bucket,
        Key=key,
        Tagging={"TagSet": [{"Key": "validation", "Value": result}]},
    )


def _move(bucket, key, dest):
    s3.copy_object(
        Bucket=bucket, Key=dest, CopySource={"Bucket": bucket, "Key": key}
    )
    s3.delete_object(Bucket=bucket, Key=key)


def handler(event, context):
    results = []
    for record in event["Records"]:
        bucket = record["s3"]["bucket"]["name"]
        # S3 URL-encodes keys in event notifications ("a b" arrives as "a+b").
        key = urllib.parse.unquote_plus(record["s3"]["object"]["key"])
        name = key.split("/", 1)[1] if "/" in key else key
        local = "/tmp/" + os.path.basename(key)

        s3.download_file(bucket, key, local)
        try:
            problems = validate(local)
        finally:
            os.remove(local)  # /tmp persists on warm starts; don't fill it

        if problems:
            report = json.dumps({"key": key, "problems": problems}, indent=2)
            s3.put_object(
                Bucket=bucket,
                Key=f"quarantine/{name}.report.json",
                Body=report.encode(),
            )
            _tag(bucket, key, "failed")
            _move(bucket, key, f"quarantine/{name}")
        else:
            _tag(bucket, key, "passed")
            _move(bucket, key, f"validated/{name}")
        results.append({"key": key, "passed": not problems, "problems": problems})
    return results

Put validate(), its constants and this handler in one file called lambda_function.py. The complete file is lambda_function.py, and the tests below are test_handler.py. A few details that matter in production: keys are decoded with unquote_plus because S3 encodes spaces as +; the temp file is removed in a finally so a warm container never fills its /tmp; and the object is tagged validation=passed or validation=failed before it moves, so the verdict travels with the file.

Deploy it

Build the package with Linux platform tags so the compiled wheel matches the Lambda runtime, wherever you build it. Lambda's python3.12 runtime is Amazon Linux 2023, so manylinux_2_34 wheels apply: 

pip install rugo \
  --target ./package \
  --platform manylinux_2_34_x86_64 \
  --python-version 3.12 \
  --only-binary=:all: \
  --implementation cp

cp lambda_function.py package/
(cd package && zip -qr9 ../function.zip .)
ls -lh function.zip

That is a 5.8 MB zip, about 15 MB unpacked: roughly 6% of Lambda's 250 MB limit and small enough for a direct upload, so there is no S3 staging step and no layer. boto3 comes with the runtime.

Create the execution role. The function needs to read, tag, write and delete objects in the bucket, plus the standard logging policy: 

BUCKET=your-lake-bucket
ACCOUNT=$(aws sts get-caller-identity --query Account --output text)
REGION=$(aws configure get region)

aws iam create-role --role-name parquet-validator \
  --assume-role-policy-document '{
    "Version": "2012-10-17",
    "Statement": [{"Effect": "Allow",
      "Principal": {"Service": "lambda.amazonaws.com"},
      "Action": "sts:AssumeRole"}]}'

aws iam attach-role-policy --role-name parquet-validator \
  --policy-arn arn:aws:iam::aws:policy/service-role/AWSLambdaBasicExecutionRole

aws iam put-role-policy --role-name parquet-validator \
  --policy-name lake-access --policy-document '{
    "Version": "2012-10-17",
    "Statement": [{"Effect": "Allow",
      "Action": ["s3:GetObject", "s3:GetObjectTagging", "s3:PutObject",
                 "s3:PutObjectTagging", "s3:DeleteObject"],
      "Resource": "arn:aws:s3:::'$BUCKET'/*"}]}'

Create the function and let S3 invoke it. IAM is eventually consistent, so if create-function complains that the role cannot be assumed, wait ten seconds and run it again: 

aws lambda create-function \
  --function-name parquet-validator \
  --runtime python3.12 \
  --role arn:aws:iam::$ACCOUNT:role/parquet-validator \
  --handler lambda_function.handler \
  --zip-file fileb://function.zip \
  --timeout 60 --memory-size 512

aws lambda add-permission \
  --function-name parquet-validator \
  --statement-id s3-invoke \
  --action lambda:InvokeFunction \
  --principal s3.amazonaws.com \
  --source-arn arn:aws:s3:::$BUCKET \
  --source-account $ACCOUNT

Then point the bucket's notifications at the function, watching only incoming/ and only .parquet keys: 

aws s3api put-bucket-notification-configuration \
  --bucket $BUCKET \
  --notification-configuration '{
    "LambdaFunctionConfigurations": [{
      "LambdaFunctionArn": "arn:aws:lambda:'$REGION':'$ACCOUNT':function:parquet-validator",
      "Events": ["s3:ObjectCreated:*"],
      "Filter": {"Key": {"FilterRules": [
        {"Name": "prefix", "Value": "incoming/"},
        {"Name": "suffix", "Value": ".parquet"}]}}}]}'

The function and the bucket must be in the same region. The prefix filter is what keeps the function from triggering itself: nothing it writes lands under incoming/.

Make it yours

  • Your contract. Edit CONTRACT and NOT_NULL. Run rugo schema your-file.parquet to see the exact type names rugo reports, and paste them in.
  • Looser schemas. To tolerate new columns, delete the "unexpected column" loop. Adding a column then passes, while removing or retyping one still fails.
  • More rules. Anything you can say as a rugo predicate is a one-line check: count rows where ("price", "<", 0) and fail if the count is not zero.
  • Alerts. Publish to SNS from the failed branch, or alarm on the quarantine prefix with an S3 event of its own.
  • Bit-level integrity. Upload with an S3 checksum (--checksum-algorithm SHA256 on aws s3 cp) and S3 guarantees the bytes you stored are the bytes that were sent. rugo's checks then cover everything the checksum can't: that the bytes are a well-formed file with the right shape.

Why this stays cheap

The function reads a footer, then streams row groups through the decoder and counts. There is no DataFrame, no pandas and no PyArrow, so a small memory setting goes a long way: start at 512 MB and raise it for your largest expected file. A 15 MB package also keeps cold starts short. For measured numbers see Reading Parquet in AWS Lambda without PyArrow and When rugo makes your Lambda cheaper.

That is the whole pipeline: one file of Python, one small package, and a bucket that only ever hands good Parquet to the people downstream.
