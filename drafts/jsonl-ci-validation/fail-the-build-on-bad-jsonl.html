Fail the build on bad JSONL

Justin Joyce · 18 November 2026 · 6 min read

github actions jsonl ci data quality how-to

Correct at time of publishing, tested with rugo 0.5.12. For up-to-date performance and feature information, see rugo.dev.

JSON Lines files turn up everywhere in a repository: test fixtures, seed data, evaluation sets, config that grew too big for YAML. One stray comma or a half-saved line and something downstream breaks hours later, far from the commit that caused it. Here is a GitHub Actions check that reads every .jsonl file on each pull request and fails the build with a message that points at the broken line.

The usual defence is hoping that someone opens the file. Nobody does: a fixture with 5,000 lines is not reviewed line by line, and the diff view of a data file is a wall of JSON. A check that runs on every pull request costs seconds, needs no service to host and no schema registry to run, and turns "someone should look at that" into a red mark on the exact change that caused it.

What the check catches

Four things go wrong with JSONL files in practice, and each is caught by a different part of rugo's reader:

  • A line that is not valid JSON. A truncated paste, a merge-conflict marker, a stray hello world. rugo's error carries the line number and byte offset.
  • A value of the wrong type. A duration that became "slow", an ID that became 1.5. Declare the type of each column and rugo parses it strictly, naming the column and the offending value.
  • A missing required field. An absent key counts as null, so one is null predicate finds records that dropped it.
  • An empty file. Valid JSON Lines technically, useless in practice.

Set up a sample repository

Start with a small dataset and a contract describing it. The contract is plain JSON: the type of each column, using rugo's type names, and the columns that must always be present. 

pip install rugo

Create the files:

mkdir -p data tools

cat > data/events.jsonl <<'EOF'
{"event_id": 1, "user": "ada", "action": "login", "duration_ms": 12.5, "ts": "2026-11-01T09:00:00Z"}
{"event_id": 2, "user": "grace", "action": "search", "duration_ms": 48.0, "ts": "2026-11-01T09:00:03Z"}
{"event_id": 3, "user": "ada", "action": "export", "duration_ms": 910.2, "ts": "2026-11-01T09:01:10Z"}
{"event_id": 4, "user": "linus", "action": "login", "duration_ms": 9.8, "ts": "2026-11-01T09:02:44Z"}
{"event_id": 5, "user": "grace", "action": "logout", "duration_ms": 3.1, "ts": "2026-11-01T09:05:00Z"}
EOF

cat > contract.json <<'EOF'
{
  "schema": {
    "event_id": "INT64",
    "user": "VARCHAR",
    "action": "VARCHAR",
    "duration_ms": "FLOAT64",
    "ts": "TIMESTAMP[us]"
  },
  "required": ["event_id", "user", "action"]
}
EOF

A quick look with rugo's own CLI confirms the file reads: 

rugo count data/events.jsonl
5

The checker

rugo count already fails on malformed JSON, but a script gives you readable messages, the type and required-field rules, and a place to grow. Save this as tools/check_jsonl.py: 

#!/usr/bin/env python3
"""Validate JSONL files against a contract. Exits 1 if any file fails.

    python tools/check_jsonl.py contract.json data/*.jsonl

contract.json:
    {"schema":   {"event_id": "INT64", "user": "VARCHAR", ...},
     "required": ["event_id", "user"]}
"""
import json
import os
import re
import sys

from rugo import jsonl


def problems(path, schema, required):
    """Return (list of problems, number of records) for one file."""
    # 1. Every line is valid JSON, and every value fits its declared type.
    #    rugo's error names the line (malformed JSON) or the column and value.
    try:
        rows = 0
        with jsonl.read_jsonl(path, explicit_schema=schema) as reader:
            for morsel in reader:
                rows += len(morsel)
    except Exception as exc:
        return [str(exc)], 0

    if rows == 0:
        return ["file has no records"], 0

    # 2. Required fields are present. An absent key counts as null.
    found = []
    for name in required:
        with jsonl.read_jsonl(
            path,
            columns=[name],
            predicates=[(name, "is null", None)],
            explicit_schema=schema,
        ) as reader:
            missing = sum(len(m) for m in reader)
        if missing:
            found.append(f"{name}: missing or null in {missing} of {rows} records")
    return found, rows


def annotate(path, message):
    """Print a GitHub Actions error annotation, pinned to a line when known."""
    line = re.search(r"at line (\d+)", message)
    where = f"file={path}" + (f",line={line.group(1)}" if line else "")
    escaped = message.replace("%", "%25").replace("\r", "%0D").replace("\n", "%0A")
    print(f"::error {where}::{escaped}")


def main(argv):
    if len(argv) < 3:
        print(__doc__)
        return 2
    with open(argv[1]) as handle:
        contract = json.load(handle)
    schema, required = contract["schema"], contract.get("required", [])

    failed = 0
    for path in argv[2:]:
        found, rows = problems(path, schema, required)
        if not found:
            print(f"ok    {path}  ({rows} records)")
            continue
        failed += 1
        for message in found:
            print(f"FAIL  {path}: {message}")
            if os.environ.get("GITHUB_ACTIONS"):
                annotate(path, message)
    print(f"\n{len(argv) - 2 - failed} passed, {failed} failed")
    return 1 if failed else 0


if __name__ == "__main__":
    sys.exit(main(sys.argv))

The first read does the heavy lifting. explicit_schema tells rugo the exact type of each column, and it then parses strictly: no guessing, no widening, and a clear error the moment a value does not fit. The second read reuses a predicate, ("user", "is null", None), and counts what comes back.

Break it on purpose

Make four bad files, one for each failure, then run the checker over everything: 

# a line cut off mid-record
{ sed -n 1,2p data/events.jsonl
  echo '{"event_id": 3, "user": "ada", "acti'
  sed -n 4,5p data/events.jsonl; } > data/truncated.jsonl

# a duration that became text
sed '3s/910.2/"slow"/' data/events.jsonl > data/types.jsonl

# a record that lost its user
sed '2s/"user": "grace", //' data/events.jsonl > data/missing.jsonl

# nothing at all
: > data/empty.jsonl

python tools/check_jsonl.py contract.json data/*.jsonl
echo "exit code: $?"
FAIL  data/empty.jsonl: file has no records
ok    data/events.jsonl  (5 records)
FAIL  data/missing.jsonl: user: missing or null in 1 of 5 records
FAIL  data/truncated.jsonl: Malformed JSONL at line 3 (byte offset 205): '{"event_id": 3, "user": "ada", "acti'
FAIL  data/types.jsonl: explicit_schema: column 'duration_ms' row 2 value 'slow' is not a valid FLOAT64 (declared type mismatch)

1 passed, 4 failed
exit code: 1

The script exits 1, which is all a CI job needs to go red. Note that row in the type error counts records from zero, so row 2 is the third record. For the malformed line, rugo reports the true line number.

Wire it into GitHub Actions

Save this as .github/workflows/validate-data.yml. It runs on pull requests that touch a .jsonl file or the checker itself, installs rugo (one wheel, no other dependencies) and feeds every tracked JSONL file to the script: 

name: validate-data

on:
  pull_request:
    paths:
      - "**.jsonl"
      - "contract.json"
      - "tools/check_jsonl.py"

jobs:
  jsonl:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v7
      - uses: actions/setup-python@v7
        with:
          python-version: "3.12"
      - run: pip install rugo
      - name: Validate every tracked .jsonl file
        run: git ls-files -z '*.jsonl' | xargs -r -0 python tools/check_jsonl.py contract.json

git ls-files means only committed files are checked, so scratch files never fail a build, and -z with xargs -0 keeps filenames with spaces intact. Because the script runs on the runner with GITHUB_ACTIONS set, every failure is also printed as a workflow annotation. GitHub shows these as red markers on the pull request, and for a malformed line the marker is pinned to that line when it is part of the diff. GitHub sets GITHUB_ACTIONS for you; set it by hand to see exactly what the runner sees: 

GITHUB_ACTIONS=true python tools/check_jsonl.py contract.json data/truncated.jsonl data/types.jsonl
echo "exit code: $?"
FAIL  data/truncated.jsonl: Malformed JSONL at line 3 (byte offset 205): '{"event_id": 3, "user": "ada", "acti'
::error file=data/truncated.jsonl,line=3::Malformed JSONL at line 3 (byte offset 205): '{"event_id": 3, "user": "ada", "acti'
FAIL  data/types.jsonl: explicit_schema: column 'duration_ms' row 2 value 'slow' is not a valid FLOAT64 (declared type mismatch)
::error file=data/types.jsonl::explicit_schema: column 'duration_ms' row 2 value 'slow' is not a valid FLOAT64 (declared type mismatch)

0 passed, 2 failed
exit code: 1

The contract is just a file in the repository, so it is reviewed like code. When a producer legitimately adds or retypes a field, the change shows up as a diff to contract.json in the same pull request as the data, and the people who care about the shape of the data see it before it merges.

Adapt it to your data

  • Your contract. Replace the schema and required list. Type names include INT64, FLOAT64, BOOL, VARCHAR, DATE and TIMESTAMP[us].
  • Several shapes of file. Keep one contract per folder and run the script once per folder, passing each contract in turn.
  • Value rules. Any predicate works as a check. Count rows where ("duration_ms", "<", 0) and fail when the count is not zero.
  • Run it before you push. The script has no CI dependency, so python tools/check_jsonl.py contract.json data/*.jsonl runs the same check locally, or from a pre-commit hook.

Everything here is one file of Python and one pip install rugo, so the job starts quickly and has nothing to cache or pin. When you also publish the data as Parquet, the same idea carries over; see Validate Parquet files the moment they land in S3.
